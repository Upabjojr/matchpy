# CLAUDE.md

This file guides Claude Code when working in this repository.

**The project guidance lives in [AGENTS.md](./AGENTS.md).** Read it first — it
covers the architecture (MatchPy core → `sympy_matching` → `sympy_wolfram` →
`rubi_rules`), the layout, how to run tests, and the conventions below. This
file only highlights the things most likely to trip you up.

## Quick reference

- **Python 3.10 or newer**; runtime deps `multiset`, `sympy`, `pydantic`. Dev setup: `make init`.
- **Core tests + doctests:** `make test`
- **A package's tests:** `pytest rubi_rules/tests/` (or `sympy_wolfram/tests/`, `sympy_matching/`)
- **One file:** `pytest <path>::<test> -x`
- **Lint:** `make check` (flake8) / `make lint` (pylint). Line length 120.

## Must-not-break rules

- **Never hand-edit `rubi_rules/rules/**`** — those files are auto-generated by
  `rubi_rules/codegen/generate.py`. Change the generator (or source FFL JSON)
  and regenerate with `python -B -m rubi_rules.codegen.generate`.
- MatchPy expression types are **`matchpy._typed.TypedModel`s** (a lightweight
  annotation-checked base that REPLACED pydantic in `matchpy/` — do not reintroduce
  pydantic there). `SymPyReplacementPattern` (in `sympy_matching/`) still uses pydantic's
  `BaseModel`; that is the only layer where pydantic remains a dependency.
- Keep the `# -*- coding: utf-8 -*-` header on every file.
- Register new SymPy↔MatchPy heads via `register_sympy_head` / the `SYMPY_NODES`
  table in `sympy_matching/operations.py`, not ad hoc.
- Rubi `Condition` failures raise `StopIteration` and are treated as "no match" —
  don't swallow or reinterpret that.

See **AGENTS.md** for the full picture.
